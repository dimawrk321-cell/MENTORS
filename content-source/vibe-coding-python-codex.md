## 2. Результат, который должен быть к концу гайда

### Техническое задание

Нужно собрать сервис, который:

- принимает `POST /predict` с JSON-полем `text`;
- передаёт текст в простую функцию-классификатор;
- возвращает `label` и `score`;
- отвечает на `GET /health`;
- отклоняет невалидные данные;
- подтверждает поведение автоматическими тестами.

### Итоговая структура

```text
ml-backend/
├── app/
│   ├── __init__.py
│   ├── main.py
│   ├── routes.py
│   ├── schemas.py
│   └── service.py
├── tests/
│   └── test_api.py
├── scripts/
│   └── call_api.py
├── AGENTS.md
├── pyproject.toml
├── uv.lock
└── .python-version
```

### Как проходит запрос

```text
клиент
  │
  └─ POST /predict
       │
       ▼
FastAPI endpoint
       │
       ▼
Pydantic-схема запроса
       │
       ▼
service.py → run_inference(text)
       │
       ▼
PredictResponse
       │
       ▼
JSON-ответ клиенту
```

Главная архитектурная идея: HTTP-слой не знает, как устроена модель. Сегодня `run_inference` считает слова. Завтра внутри неё может появиться `sklearn`, PyTorch, `transformers`, локальная LLM, отдельный inference server или внешний API — контракт `/predict` при этом не обязан меняться.

### Роли файлов

| Файл | Ответственность |
| --- | --- |
| `app/main.py` | Собирает и настраивает приложение |
| `app/routes.py` | Описывает HTTP-endpoints |
| `app/schemas.py` | Проверяет вход и описывает выход |
| `app/service.py` | Выполняет бизнес-логику или inference |

Для этого проекта не нужны `repositories`, `use_cases`, `domain`, `ports`, `adapters`, CQRS и контейнер зависимостей. Дополнительный слой полезен только тогда, когда решает уже появившуюся проблему, а не когда делает маленький сервис похожим на большую систему.

### Зафиксируй контракт API

Требования:

- `GET /health` возвращает `{"status": "ok"}`;
- `POST /predict` принимает `{"text": "..."}`;
- ответ `POST /predict`: `{"label": "short", "score": 0.3}`;
- длина `text` — от 1 до 5000 символов;
- endpoint занимается HTTP, `service.py` — вычислением;
- функции синхронные;
- временная логика считает слова: пять и больше — `long`, иначе `short`; `score = min(word_count / 10, 1)`.

:::spoiler{title="Промпт: реализовать контракт"}
```text
Цель:
Реализуй API-контракт сервиса.

Контекст:
- Изучи существующий каркас и AGENTS.md.
- GET /health должен вернуть {"status": "ok"}.
- POST /predict принимает JSON {"text": "..."}.
- Ответ: {"label": "short|long", "score": число от 0 до 1}.

Ограничения:
- Pydantic-модели находятся в app/schemas.py.
- text: минимум 1, максимум 5000 символов.
- app/routes.py содержит только HTTP-логику.
- app/service.py содержит run_inference(text).
- Не подключай реальную модель и не добавляй новые слои.
- Используй синхронные функции.

Временная логика:
- Посчитай слова через text.split().
- Если слов 5 или больше, label = "long", иначе "short".
- score = min(word_count / 10, 1.0).

Готово, когда:
- Оба endpoint работают.
- Невалидный text отклоняется FastAPI.
- Есть тесты для health, short, long и пустой строки.
- pytest и Ruff проходят.
```
:::

### Эталон минимальной реализации

`app/schemas.py`:

```python
from pydantic import BaseModel, Field


class PredictRequest(BaseModel):
    text: str = Field(min_length=1, max_length=5000)


class PredictResponse(BaseModel):
    label: str
    score: float
```

`app/service.py`:

```python
def run_inference(text: str) -> tuple[str, float]:
    word_count = len(text.split())
    label = "long" if word_count >= 5 else "short"
    score = min(word_count / 10, 1.0)
    return label, score
```

`app/routes.py`:

```python
from fastapi import APIRouter

from app.schemas import PredictRequest, PredictResponse
from app.service import run_inference

router = APIRouter()


@router.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok"}


@router.post("/predict", response_model=PredictResponse)
def predict(payload: PredictRequest) -> PredictResponse:
    label, score = run_inference(payload.text)
    return PredictResponse(label=label, score=score)
```

`app/main.py`:

```python
from fastapi import FastAPI

from app.routes import router

app = FastAPI(title="ML-ready Prediction Service", version="0.1.0")
app.include_router(router)
```

### Проверь API вручную

Открой Swagger по адресу `http://127.0.0.1:8000/docs` и выполни три проверки:

2. `POST /predict` с `{"text": "hello"}` → `label: short`, `score: 0.1`.

### Вызови API вторым Python-процессом

`scripts/call_api.py`:

```python
import argparse

import httpx


def main() -> None:
    parser = argparse.ArgumentParser()
    parser.add_argument("text")
    parser.add_argument("--url", default="http://127.0.0.1:8000/predict")
    args = parser.parse_args()

    response = httpx.post(args.url, json={"text": args.text}, timeout=5.0)
    response.raise_for_status()
    print(response.json())


if __name__ == "__main__":
    main()
```

Оставь сервер в первом терминале, открой второй и выполни:

```bash
uv run python scripts/call_api.py "one two three four five"
uv run python scripts/call_api.py "hello"
```

Ожидаемые ответы:

```text
{'label': 'long', 'score': 0.5}
{'label': 'short', 'score': 0.1}
```

## 5. Система промптов для Codex

Плохой запрос звучит так: «Сделай production-ready ML microservice». В нём нет границ, поэтому Codex вынужден додумывать архитектуру, инфраструктуру и критерии готовности.

Рабочий формат:

1. **Goal** — один проверяемый результат.
2. **Context** — существующие файлы и текущий контракт.
3. **Constraints** — что нельзя менять и добавлять.
4. **Done when** — команды и наблюдаемые признаки готовности.

Применяй один цикл:

```text
ТЗ → план → каркас → реализация → тесты → исправления → финальный review
```

## 6. Финальная симуляция собеседования

На этот блок отведи 75 минут. Начни с новой пустой папки `interview-practice` и не копируй готовые файлы из предыдущего проекта.

### Техническое задание

Создай сервис, который:

1. отвечает на `GET /health`;
2. принимает `POST /analyze` с телом `{"values": [1.0, 2.0, 3.0]}`;
3. отклоняет пустой список;
4. возвращает `count`, `mean` и `maximum`;
5. подтверждает поведение автоматическими тестами.

### Объяснение для интервьюера

К концу симуляции ты должен коротко объяснить:

- `main.py` создаёт приложение и подключает router;
